Overview

  • Deliver the full CONTACT analysis. Turn the repository’s Python 2 network extractor and the original supplementary pathway generator into an installable modern Python package with an import-safe API and a matching CLI.
  • Make scientific compatibility explicit. Preserve documented clash, relief, alternate-conformation, and pathway rules; distinguish bug corrections and requested extensions from legacy behavior. Reconcile source-versus-paper discrepancies before declaring reproduction successful.
  • Scale by independent inputs. Support headless, isolated analyses under external schedulers. No embedded job manager, model-building pipeline, or automatic hydrogen preparation.
  • Keep results reusable and auditable. Expose pathways, weighted networks, and counts in memory; export JSON, CSV, and optional PNGs with parameters, provenance, and completion status.
  • Optimize exact computation, not the science. Address contact-search cost, pathway enumeration, postprocessing, graph aggregation, and output overhead. Accept optimizations only with correctness comparisons and measured runtime/memory evidence.

  • Search scope: search within each chain by default, without merging equal residue numbers across chains. Cross-chain mode searches the selected structure as a whole. Biological assembly expansion is separately opt-in and requires an explicit assembly identifier; missing assembly metadata is an error, not a silent fallback.
  • Identity and chemistry: retain model, chain, residue number, insertion code, alternate conformation, and assembly-copy identity. Keep ligands/cofactors relevant to CONTACT, particularly NADP in DHFR. Assembly copies remain distinct even when original residue identifiers match.
  • Defaults: clash percentile 0.30, maximum pathway length 100, all-atom analysis, relief threshold 0.90, and minimum network size 3. Expose the scientific settings, side-chain-only mode, and existing pathway-length/residue filters through the API and CLI.

Reject a whole pathway when a required relief is below threshold. Handle the initial no-predecessor relief marker separately from genuine zero relief. Build weighted residue connections and remove components below the configured network minimum.

Optimizations included

  • Contact evaluation: avoid exhaustive atom-pair work and dense all-conformer storage where exact geometric pruning is possible. Preserve all interactions required for relief decisions, the clash-percentile population, and threshold ties; absence from a clash candidate list must not mean absence of a relief interaction.
  • Pathway generation: reuse unchanged contact calculations and reduce repeated copying, file reopening, and serialization during enumeration. Keep output ordering stable enough for reproducible partial runs. No approximate search, random sampling, or unproven pruning.
  • Pathway postprocessing: reduce repeated pairwise containment work and duplicate storage while preserving ordered contiguous-subpath semantics and the original treatment of reversed paths.
  • Network extraction: eliminate full-graph scans for each pathway edge, repeated membership scans, and unnecessary retained pathway copies. Aggregate weights and connected components efficiently without changing count definitions.
  • Workload efficiency: avoid plotting unless requested, keep workers/processes isolated, and avoid nested parallelism that competes with scheduler allocations. Large outputs may still require substantial storage; do not promise constant-memory in-memory results.
  • Measurement gate: compare reference and optimized results on DHFR and small exact cases, then record wall time, peak memory, output size, candidate counts, and truncation behavior on larger multi-conformer and multi-chain inputs. Choose further compiled acceleration only if these measurements justify it; no speculative GPU/distributed execution layer.
